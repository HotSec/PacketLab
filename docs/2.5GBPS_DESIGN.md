# 2.5Gbps 支撑方案

## 目标

```
2.5Gbps = 312.5 MB/s
10KB/req →  31,250 req/s  ✅ SQLite 可达
2KB/req  → 156,250 req/s  ❌ SQLite 瓶颈 (54K)
500B/req → 625,000 req/s  ❌ 需要新架构
```

## 核心瓶颈

SQLite 单库写入 ~54K req/s，无法支撑 156K+ 小包场景。

## 方案：内存环形缓冲区 + 异步落盘

```
                    ┌─────────────┐
  网卡 → BPF → 包解析 │ 4 Workers  │ → Parse HTTP
                    └──────┬──────┘
                           │ emitNonBlocking
                           ▼
              ┌────────────────────────┐
              │   Ring Buffer (128MB)  │  ← 内存热路径
              │   262K entries max     │     零阻塞
              │   head/tail 原子操作   │
              └───────┬────────────────┘
                      │ async flush
              ┌───────▼────────┐
              │ 4 Writer Pool  │  ← 后台落盘
              │ batch 500/50ms │
              └───────┬────────┘
                      │
              ┌───────▼────────┐
              │    SQLite      │  ← 持久化
              └────────────────┘
```

## 组件设计

### 1. MemRingBuffer

```go
type MemRingBuffer struct {
    buf     []Record        // 固定 128MB 环形数组
    head    atomic.Uint64   // 写入位置
    tail    atomic.Uint64   // 读取位置
    dropped atomic.Uint64   // 丢弃计数
    mu      sync.Mutex
}
```

**特性**:
- 预分配 128MB，零运行时分配
- 写入: CAS head，覆盖最旧条目（tail 前移）
- 读取: 批量读取 tail→head 范围
- 背压: head-tail > 80% → 触发紧急 flush
- dropped 计数: 监控丢包率

### 2. AsyncWriterPool

```go
type AsyncWriterPool struct {
    store    *store.Store
    buf      *MemRingBuffer
    workers  int  // 4
    interval time.Duration  // 30ms
}
```

**特性**:
- 4 goroutine pool，轮询读取 ring buffer
- 批量 flush: 每次读取 500-1000 条
- 写入 SQLite 后标记 consumed
- 监控写入延迟: > 50ms → 增加 worker

### 3. 读取路径

前端请求列表: 先查 ring buffer（最近 N 条），再查 SQLite（历史）。

## 吞吐计算

```
Ring Buffer: 128MB / (500B avg) = 262,144 entries
写入速率: 内存写入 ~10M req/s (纯内存)
SQLite 写入: 4 workers × 54K/4 ≈ 54K req/s (共享单 DB)

2.5Gbps 持续流量:
  10KB/req:  31,250 req/s → ring buffer 吸收 → SQLite 54K ✅
  2KB/req:  156,250 req/s → ring buffer ← SQLite 54K 跟不上
                                   ↓
  短期 2KB 突发: ring buffer 262K / 156K = 1.7s 缓冲
  持续 2KB: SQLite 成为瓶颈, 需换存储引擎
```
